## Why

Full blocks containing many expensive transactions create a proving-latency bottleneck. Today the smallest provable unit is an entire block — every transaction is proven monolithically inside a single zkVM execution. When a block is packed with high-cost transactions (large contract deployments, complex DeFi interactions), proving time is dominated by one long-running job with no opportunity for parallelism.

By decomposing a block's ordered transaction body into independently provable **partial executions**, we enable parallel proving across multiple machines. Each partial carries the transactions it proved plus the full per-transaction `ResultAndState` trace it produced. At aggregation time those cached results flow back through the standard block executor; a single per-tx prestate-authentication check inside the EVM layer ensures each cached result matches the live `TrieDB`, and a per-block `ExpectedState` snapshot binds the OP-specific L1Block contract reads that happen outside the per-tx state diff. The output is indistinguishable from today's monolithic block proof, so block stitching, derivation, fault proofs, and on-chain verification require no changes.

## What Changes

- **Unified `CachedEvm` / `CachedEvmFactory`.** A single `Evm`-trait wrapper replaces four earlier types (tracing evm, chunking evm, their factories). Depending on how it is constructed it serves as a transparent pass-through, a trace collector (capturing per-tx `(tx_hash, PartialResultAndState, expected_state)` triples during host pre-execution), or a cached-serve EVM that returns witness-supplied results AFTER (a) authenticating their `original_info` / `original_value` against the live `TrieDB`, (b) on first cached serve per partial, asserting that the partial's `expected_state` snapshot matches the live DB's view of the OP-specific L1Block slot set. Zero vendored code changes.
- **`PartialExecution` struct.** A proven transaction subsequence carries five fields: `tx_hashes`, `results: Vec<PartialResultAndState>`, `expected_state: Vec<ExpectedStateEntry>`, `block_env`, `op_block_ctx`. There are no pre/post memory-DB hashes, no EVM-accumulator state, no `tx_count`, no positional block metadata — everything else is derived at verification time. A `precondition_hash()` method returns the partial's commitment; a `boot_info(&boot)` method derives the partial's `BootInfo`; a `split(partials_per_block)` method produces sub-partials each carrying the running `ExpectedState` snapshot at its starting position.
- **`PartialResultAndState` canonical form.** A revm-mirroring sorted-Vec representation (`PartialStateEntry { address, account: PartialAccount }`, `PartialAccount { info, original_info, transaction_id, status, storage: Vec<PartialStorageEntry> }`, `PartialStorageEntry { slot, slot_value }`). All entries sorted by address / slot at construction. Lives in `crates/kona/src/evm/partial.rs` with `From<ResultAndState<OpHaltReason>>` and `From<PartialResultAndState> for ResultAndState<OpHaltReason>` round-trips, plus rkyv `Archive`/`Serialize`/`Deserialize` derives. Replaces using revm's `HashMap`-backed `ResultAndState` directly so canonical hashing and rkyv encoding are deterministic without the per-call `BTreeMap` sort dance.
- **`ExpectedState` mechanism.** `ExpectedStateEntry { address, account: ExpectedAccount { exists, info, storage: Vec<ExpectedStorageEntry> } }` snapshots a fixed set of OP-specific addresses and slots that the block executor reads outside the normal per-tx state diff (currently `L1_BLOCK_CONTRACT` × {`L1_BASE_FEE_SLOT`, `ECOTONE_L1_FEE_SCALARS_SLOT`, `L1_OVERHEAD_SLOT`, `L1_SCALAR_SLOT`, `ECOTONE_L1_BLOB_BASE_FEE_SLOT`, `OPERATOR_FEE_SCALARS_SLOT`}). `capture_required_expected_state(db)` reads the snapshot; `apply_result_to_expected_state(&mut snapshot, &result)` advances it tx-by-tx for the splitter; `canonicalize_expected_state(snapshot)` enforces the sort order. The host captures this per-tx in `PartialExecutionTrace`; the splitter folds it forward when slicing a block-wide partial into sub-partials; the guest re-derives it at chunk start.
- **`PartialExecutionWitness` struct.** The single-partial proof witness carries `transactions` + a pre-state `CacheState` (seeded into `State::builder().with_cached_prestate(...)`) + `block_env` + `op_block_ctx`. It does NOT carry `expected_state` explicitly: `cache_results` seeds the `expected_state` snapshot into `cache` during witness construction (alongside the chunk's per-tx prestate), and the guest re-derives the snapshot via `capture_required_expected_state` against `cache` to compute `hash_expected_state` at chunk start.
- **Precondition extension.** A new `partial_executions: B256` field on `Precondition` (third exclusive mode alongside execution-only and derivation/proposal), with digest `compute_pe_trace(results_hash, block_ctx_hash, expected_state_hash)` — a three-input `SHA256(results_hash || block_ctx_hash || expected_state_hash)`. `results_hash` folds each account's `original_info` into the canonical encoding (binding per-tx prestate authentication); `expected_state_hash` binds the once-per-partial OP-specific L1Block snapshot.
- **Partial proving mode.** A new `PARTIAL EXECUTION` branch in `run_core_client` activated by `boot.l1_head == 0xFF..FF`. It seeds the carried `CacheState` into `State`, re-derives `expected_state` against the seeded state, runs every tx through the standard `OpBlockExecutor` with `CachedEvmFactory` capturing traces, and emits a `ProofJournal` with `l1_head = 0xFF..FF` and `agreed_l2_output_root == claimed_l2_output_root`.
- **Unified aggregation path.** Both the `EXECUTION ONLY` and `DERIVATION & EXECUTION` branches of `run_core_client` build their executor with `CachedEvmFactory::new_with_traces(partial_executions, partials_collector)`. With an empty partials vec this is byte-identical to `OpEvmFactory::default()`; with populated partials it serves cached results with inline prestate + expected-state authentication. No separate "aggregation mode".
- **Stitching extension.** Two new free functions: `precompute_pe_boots` (run BEFORE `run_core_client` consumes its partials) produces `(precondition_hash, StitchedBootInfo)` pairs; `stitch_partial_executions` reconstructs the partial `ProofJournal` and verifies it against `proven_fpvm_journals`. `KonaStitchingClient` short-circuits the rest of stitching when the booted `l1_head == 0xFF..FF` (the partial proof emits its own packed journal).
- **Witness threading.** `Witness` gains `pe_witness: Option<PartialExecutionWitness>` and `partial_executions: Vec<Vec<PartialExecution>>`. Both thread through `run_stateless_client` → `run_stitching_client` → `run_core_client` and through `StitchingClient` implementations in hana / hokulea / prover witgen.
- **Prover-side dispatch.** The prover accepts `--num-block-partials` (default `0` = monolithic; positive `N` = up to `N` partials per block via `PartialExecution::split`). `prove.rs` runs `concurrent_preflight` (which now returns captured `Vec<Vec<PartialExecution>>` alongside execution outcomes), then dispatches one partial proof job per sliced sub-partial in parallel, accumulating receipts and a `PartialsCache: BTreeMap<u64, Vec<PartialExecution>>` keyed by parent block number. The aggregation pass receives the cache and re-supplies it as the `partial_executions` vector. `client/native::run_native_client` calls `PartialExecutionWitness::from_preflight(partial, &exec)` when `args.kona.l1_head == 0xFF..FF` to assemble the partial proof witness on the fly.

## Capabilities

### New Capabilities

- `partial-precondition` — Extension of `Precondition` with a `partial_executions` field and the three-input `compute_pe_trace` digest (`results_hash || block_ctx_hash || expected_state_hash`).
- `partial-proving` — The `PARTIAL EXECUTION` branch in `run_core_client` that executes a single `PartialExecutionWitness` against a `State<TrieDB>` seeded with the witness `CacheState`, re-derives `expected_state`, captures per-tx results, and emits a partial `ProofJournal`.
- `partial-aggregation` — `PartialExecution` struct, `CachedEvm`'s per-tx prestate authentication and once-per-partial `ExpectedState` check, and the `precompute_pe_boots` + `stitch_partial_executions` pipeline that verifies partial receipts alongside execution-only proofs.
- `partial-witness-construction` — Host-side assembly of `PartialExecution` entries from the `CachedEvmFactory` trace collector (`recover_collected_partials` + `build_single_partial_for_block`) and of `PartialExecutionWitness` from a `PartialExecution` + `Execution` (`PartialExecutionWitness::new` / `::from_preflight` + `cache_results`).
- `cached-evm-factory` — The unified `CachedEvm` / `CachedEvmFactory` EVM wrapper replacing the four-type tracing/chunking split, plus the `EvmFactory`-generic refactor of `CachedExecutor`.
- `prover-partial-dispatch` — `--num-block-partials` configuration on `ProvingArgs`, parallel dispatch in `prove.rs` (one `compute_oneshot_task` per sub-partial), the `PartialsCache` keyed by parent block number, and `run_witgen_client`'s `partial_executions` threading into `Witness.partial_executions`.

### Modified Capabilities

_(none — partial execution is transparent to existing block stitching, derivation, and fault proof systems)_

Extended `rkyv/evm.rs` with `CacheStateRkyv`, `BlockEnvRkyv`, `OpBlockExecutionCtxRkyv`, `AccountRkyv`, `EvmStateRkyv`, `ExecutionResultRkyv`, `AccountInfoRkyv`, `AccountStatusRkyv`, `EvmStorageSlotRkyv`, and the `halt_reason_rkyv` / `op_halt_reason_rkyv` helpers.
- **`crates/prover/src/`** — Modified `args.rs` (`num_block_partials: usize` ProvingArgs field; default `0`). Modified `client/witgen.rs` (`run_witgen_client` threads `pe_witness` and `partial_executions`, captures partials via `recover_collected_partials` after the core run). Modified `tasks.rs` (`CachedTask` carries `partial_executions: Vec<Vec<PartialExecution>>` and `partials_cache`; `compute_cached_proof` updates `proof_journal.precondition_hash` to `Precondition::default().partial(partial.precondition_hash()).digest()` when `boot.l1_head == 0xFF..FF`). Modified `preflight.rs` (`concurrent_preflight` returns `Vec<Vec<PartialExecution>>` alongside the execution trace).
- **`build/risczero/*/src/main.rs`** — Entry points thread `pe_witness` and `partial_executions` through to `run_stateless_client`.
- **Vendored code (`optimism/rust/`)** — No changes.
- **External dependencies** — No new dependencies. Uses existing revm primitives.
- **Backward compatibility** — Fully backward compatible. A witness with `pe_witness = None` and empty `partial_executions` exercises the same code path as before (with `CachedEvmFactory` degrading to an `OpEvmFactory` pass-through). Existing proofs, stitching receipts, and fault-proof games are unaffected. `--num-block-partials 0` (the default) reproduces monolithic proving byte-for-byte.
