## Context

The `crates/contracts/build.rs` compiles Solidity contracts via the `foundry_compilers` Rust crate (v0.11.6) during `cargo build`. It currently uses `ProjectPathsConfig::builder().build_with_root("foundry")` which sets up directory paths but does **not** read remappings from `foundry.toml`.

After the migration from vendored flat files to git submodule dependencies with namespace-based remappings (`@optimism/`, `@risc0/`, `@solady/`, etc.), `cargo build -p kailua-contracts` fails because `solc` cannot resolve any `@`-prefixed import paths. `forge build` succeeds because the Forge CLI reads `foundry.toml` natively.

## Goals / Non-Goals

**Goals:**
- Make `cargo build -p kailua-contracts` compile successfully with the new remapped imports
- Keep `build.rs` in sync with `foundry.toml`/`remappings.txt` without duplicating remapping definitions
- Ensure rebuilds trigger on remapping or dependency changes

**Non-Goals:**
- Parsing the full `foundry.toml` TOML structure (overkill for this fix)
- Changing the Solidity source files or their import paths
- Upgrading the `foundry_compilers` crate version

## Decisions

### Decision 1: Read remappings from `remappings.txt` (not `foundry.toml`)

**Choice**: Parse `foundry/remappings.txt` line by line using `Remapping::from_str()`.

**Alternatives considered**:
- *Parse `foundry.toml` with the `toml` crate*: Requires adding a dependency and dealing with TOML profile structure. Overkill when `remappings.txt` already exists and contains the same data in a simpler format.
- *Hardcode remappings in `build.rs`*: Violates DRY and will drift from `foundry.toml` over time.
- *Use `foundry-config` crate*: Heavy dependency that pulls in Foundry's full config stack. Not appropriate for a build script.

**Rationale**: `remappings.txt` is auto-generated by `forge` and contains the complete set of remappings in a trivial `name=path` format. The `foundry_compilers` crate already provides `Remapping::from_str()` to parse this format. This is the lightest, most maintainable approach.

### Decision 2: Add `cargo:rerun-if-changed` for dependency-related files

**Choice**: Add rerun directives for `foundry/remappings.txt`, `foundry/foundry.toml`, and `foundry/lib`.

**Rationale**: The current build.rs only watches `src` for changes. With git submodule dependencies, changes to remappings or library contents should also trigger recompilation. Watching `foundry/lib` covers submodule updates.

## Risks / Trade-offs

- **[Risk] `remappings.txt` out of sync with `foundry.toml`** → Mitigation: `forge` regenerates `remappings.txt` on build. The `remappings.txt` is the canonical source that `forge` itself reads. Document that `forge build` should be run after changing `foundry.toml` remappings.
- **[Risk] `foundry/lib` watch is coarse-grained** → Mitigation: Submodule updates are infrequent. False-positive rebuilds are cheap compared to missing a real change.
